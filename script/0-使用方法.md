## 1- 环境与数据准备

正式训练在 Linux + NVIDIA GPU 机器执行，建议 Python 3.11。创建环境后，先安装与训练机驱动匹配的 CUDA 版 PyTorch 和 torchvision，再安装项目依赖。以下命令均在仓库根目录运行：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
# 在此先安装匹配训练机 CUDA 的 torch 和 torchvision
python -m pip install -r requirements.txt
python -c "import torch; assert torch.cuda.is_available(), 'CUDA unavailable'; print(torch.__version__, torch.cuda.get_device_name(0))"
git submodule update --init third_party/dinov3
test -f data/model/dinov3_vitl16_pretrain_lvd1689m-8aa4cbdd.pth

# 默认读取 data/00-origin_data，输出到 data/01-train_data/<日期>
python script/01-genTrainData.py
# 将 configs/default_oven.yaml 的 data.root 指向本次打印的实际目录
python script/02-checkTrainData.py --config configs/default_oven.yaml
```

本次已生成 `data/01-train_data/20261017`，train / val / test 分别为 7275 / 910 / 908 张，默认配置已经同步。搬到训练机时需复制数据和预训练权重，Git 不包含这些大文件。已有生成结果可直接使用，无需重跑生成器；重跑会新建目录，需要同步修改 `data.root`。

生成器支持 `--src <原始目录> --dst <输出根目录>`，按型号分层划分，并将同图多份标注、文件内容相同的图片绑定到同一划分。数据按划分放在 `<root>/<split>/` 下，每张图片旁边放同名 JSON 标注。
标注工具导出的 1.x 格式（字段在 `annotations` 下，用"无"表示空）和设计文档第 6 节的规范格式都能直接读。
多个批次可以在配置里写成列表，但应先检查批次之间是否重复。

预检脚本使用真实入库解析、训练增强及 PK 采样读取首个 batch，检查标签有效性和跨划分内容重复，默认报告在 `output/preflight/data_check.json`；退出码非零时先处理报告中的错误。可用 `--batches 4 --num-workers 0 --output <报告路径>` 调整读取量和报告位置。该预检不加载骨干或执行训练。在本机只做数据检查时，可以激活已有的 `wahaha` 环境后运行，无需 CUDA。

新型号先在 `configs/device_profile.json` 补上 `rack_count / floor_usable / cavity_group / accessories`，否则该型号的样本会被当作标注错误。

当前设备配置表中的部分底板可用性、内腔分组和附件支持仍是占位值，正式训练前需核实。当前层位模型只预测单个层位；482 张多层图片在生成时保留其它属性，层位设为 `null`，原值存于 `training_preparation.multi_rack_level`，不训练层位头。

本批 `CQ09-i9` 只有 13 张（11 / 1 / 1），外部未知只有 11 张（9 / 1 / 1），验证、测试各只有一张相关样本，应谨慎解读按型号指标和拒识阈值。相同图片绑定划分仍不能排除视频邻帧泄漏，最终评估应额外保留按视频或拍摄场次分组的独立测试集。

## 2- 启动训练

```bash
# 前台运行
python train.py --config configs/default_oven.yaml --device cuda

# 后台运行（终端输出在 logs/oven/<日期>/，训练日志写在输出目录的 train.log）
GPU_ID=0 bash script/3-启动训练.sh
```
训练前会做入库校验：

- 硬错误（类别不在类别表、层位超出 rack_count、型号不在 Device Profile、图片缺失、JSON 损坏等）默认直接报错并列出文件，设 `data.on_error: skip` 可跳过这些样本；
- 规范类警告（如一体机内有物品但层位为空、导轨层却没有附件）默认提示；各任务只使用其有效标签，层位缺失不影响其它有效属性，设 `data.strict: true` 可把警告按错误处理；
- 入库通过后的问题明细写在输出目录的 `label_issues.json`；前置失败详情可通过数据预检报告查看。

训练结束后自动执行阶段 2：用 `ckpt_best.pt` 建特征库，在验证集上标定 tau、多标签逐类阈值和层位置信度阈值，再评估测试集。

默认是 ViT-L/16、368×640、batch 16、全部 24 层 LoRA；显存不足时可复制配置，先减少 `trainparams.batch_size` 或 `model.lora_last_n_blocks`，同时满足下述 SupCon 采样约束。

预训练骨干的所有参数和持久缓冲区必须完整、形状匹配，否则加载阶段直接报错，不能继续训练。常见 checkpoint 前缀会自动对齐，额外的训练头权重会被忽略。

使用 `sampler.type: pk`、`loss.metric: supcon` 且 `loss.weights.proj > 0` 时，每个 batch 至少包含两个 `cavity_group`，每组至少两张一体机图片。训练 batch size 至少为 4，配置的 `p_groups` 至少为 2，训练数据也必须有至少两个组，否则会在构建训练 DataLoader 时报错。采样器会按 batch 容量下调实际 P，并在必要时降低非一体机配额，调整会写入日志；batch size 为 4 时全部配额用于一体机。ArcFace 或关闭 Proj loss 时不要求这些 SupCon 条件。

验证和测试 loss 分任务按有效标注样本数汇总，再应用任务权重得到总 loss。缺标注的样本不会稀释该任务的平均值；整套数据没有有效标注的任务记为 0。SupCon 按同时有正、负样本的有效 anchor 汇总，其数值仍依赖 batch 内的样本组合，跨实验比较该项时应保持验证 batch 和样本顺序一致。

## 3- 续训

```bash
python train.py --resume output/oven/<YYMMDD_HHMMSS>/ckpt_last.pt --device cuda
# 或
RESUME_PATH=output/oven/<YYMMDD_HHMMSS>/ckpt_last.pt bash script/3-启动训练.sh
```
默认沿用 checkpoint 里保存的配置；想加轮数时再传 `--config`。
新训练自动创建按上海时间命名的秒级目录，同秒冲突自动添加后缀。`--output_dir` 仅接受不存在或为空的目录；续训沿用原 checkpoint 目录，保留原有最佳权重和指标历史。

## 4- 从冻结骨干基线继续做 LoRA 微调

默认配置已经开启 LoRA。若先用 `model.use_lora: false` 训练了冻结骨干基线，复制一份配置，设 `model.use_lora: true`，然后从基线的 best 开始：
```bash
python train.py --config configs/<阶段4配置>.yaml --init output/oven/<阶段1目录>/ckpt_best.pt
# 或
CONFIG_PATH=configs/<阶段4配置>.yaml INIT_PATH=output/oven/<阶段1目录>/ckpt_best.pt bash script/3-启动训练.sh
```
骨干变动后，结束时会用新权重重建特征库、重新标定所有阈值。
`model.lora_last_n_blocks: N` 表示仅在最后 N 个 block 注入 LoRA，0 表示全部。当前不支持直接解冻骨干原始权重，`model.unfreeze_last_n_blocks` 不是有效功能配置。

## 5- 输出（output/oven/<YYMMDD_HHMMSS>/）

| 文件 | 内容 |
|---|---|
| `ckpt_best.pt` / `ckpt_last.pt` | 各任务头及 LoRA 权重，冻结的骨干不保存；last 额外带优化器状态用于续训 |
| `gallery.pt` | 型号特征库：`proj`（Proj Head 特征）和 `cls`（DINOv3 CLS）两套；`meta.fingerprint` 是绑定的权重版本 |
| `calibration.json` | 阶段 2 标定结果：tau、is_oven / food 阈值、容器和附件逐类阈值、层位置信度阈值；`sources` 注明每项是标定值还是默认值 |
| `val_report.json` / `test_report.json` | 用标定后阈值的详细评估：逐类 P/R/AP、层位逐层准确率和按型号的混淆矩阵、型号检索、级联误差 |
| `label_issues.json` | 入库校验的错误与警告明细 |
| `training_metrics.json` / `training_curves.png` | 每轮各项 loss、各头梯度范数、验证指标 |
| `train.log` / `config.yaml` / `device_profile.json` | 日志与本次训练实际使用的配置快照 |

## 6- 可选：留一型号验证

阶段 2 完成后，可按 `cavity_group` 逐组留出、重新训练并评估新型号拒识及入库后识别：

```bash
python script/4-留一型号验证.py --run output/oven/<run> --device cuda
# 调试时可缩短每折轮数，或只选部分内腔组
python script/4-留一型号验证.py --run output/oven/<run> --device cuda --epochs 10 --groups G5A,G5B
```

默认每折轮数与原训练相同，总耗时约为多次完整训练；完成的折会复用。使用 `--retrain` 重做时，旧折目录保留为同级的 `.previous_<时间戳>` 归档。报告为 `<run>/loo_report.json`，默认还会更新 `calibration.json` 并备份原文件；`--no_apply` 只输出报告。每折仍需满足 SupCon 至少两个训练组的约束。若阶段 2 已用真实外部样本标定 tau，脚本会保留该 tau，因此本批只有一个外部验证样本的局限仍需通过补充独立数据解决。

## 7- 单张推理与 ONNX 导出

```bash
# 先修改 5-infer-dir.py 顶部 RUN_DIR、INPUT_PATH、DEVICE
python script/5-infer-dir.py
python script/6-export_onnx.py --run output/oven/<run> --check_input <图片或目录> --check_images 8
python script/7-infer_onnx.py --onnx_dir output/oven/<run>/onnx --input <图片或目录>
```

`script/5-infer-dir.py` 无命令行参数，配置项是 `RUN_DIR`、`INPUT_PATH`、`DEVICE`、`VIS_DIR` 等。相对路径以项目根目录为基准，递归处理目录图片，对有同名 JSON 的图片打印对照准确率并把可视化保存到 `<RUN_DIR>/vis/<输入目录名>/{true,false}/`；同名可视化目录重跑时会重建。该脚本不输出 predictions JSON，无标注图片会跳过对照可视化。ONNX 推理支持无标注图片，并把结果 JSON 默认保存到 `<onnx_dir>/predictions/<输入名>.json`。

PT / ONNX 推理脚本固定使用 `batch_size=1`，目录内的图片逐张处理；训练和验证仍使用训练配置中的 batch size。ONNX 输入为固定 `[1,3,H,W]`，H、W 取训练配置。导出检查的图片可以有多张，但每次前向都只有一张；检查通过后写入 `export_check.json`。LoRA 合并或 PT / ONNX 对齐失败时，导出会报错，写入 `export_check.failed.json`，并保留原部署包。
