## 1- 准备数据
数据按划分放在 `<root>/<split>/` 下，每张图片旁边放同名 JSON 标注，例如 `data/model/0904/{train,val,test}/`。
标注工具导出的 1.x 格式（字段在 `annotations` 下，用"无"表示空）和设计文档第 6 节的规范格式都能直接读。
多个批次可以在配置里写成列表：`data.root: [data/model/0904, data/model/0915]`。

新型号先在 `configs/device_profile.json` 补上 `rack_count / floor_usable / cavity_group / accessories`，否则该型号的样本会被当作标注错误。

## 2- 启动训练
```bash
# 前台运行
python train.py --config configs/default_oven.yaml --device cuda

# 后台运行（终端输出在 logs/oven/<日期>/，完整日志同时写在输出目录的 train.log）
GPU_ID=0 bash script/3-启动训练.sh
```
训练前会做入库校验：
- 硬错误（类别不在类别表、层位超出 rack_count、型号不在 Device Profile、图片缺失、JSON 损坏等）默认直接报错并列出文件，设 `data.on_error: skip` 可跳过这些样本；
- 规范类警告（如一体机内有物品但层位为空、导轨层却没有附件）只提示、不参与对应的 loss，设 `data.strict: true` 可按错误处理；
- 所有问题的明细写在输出目录的 `label_issues.json`。

训练结束后自动执行阶段 2：用 `ckpt_best.pt` 建特征库，在验证集上标定 tau、多标签逐类阈值和层位置信度阈值，再评估测试集。

## 3- 续训
```bash
python train.py --resume output/oven/<YYMMDD_HHMMSS>/ckpt_last.pt
# 或
RESUME_PATH=output/oven/<YYMMDD_HHMMSS>/ckpt_last.pt bash script/3-启动训练.sh
```
默认沿用 checkpoint 里保存的配置；想加轮数时再传 `--config`。

## 4- 阶段 4（可选）：解冻最后几层 / LoRA
复制一份配置，把 `model.unfreeze_last_n_blocks` 设为 N，或设 `model.use_lora: true`，然后从阶段 1 的 best 开始：
```bash
python train.py --config configs/<阶段4配置>.yaml --init output/oven/<阶段1目录>/ckpt_best.pt
# 或
CONFIG_PATH=configs/<阶段4配置>.yaml INIT_PATH=output/oven/<阶段1目录>/ckpt_best.pt bash script/3-启动训练.sh
```
骨干变动后，结束时会用新权重重建特征库、重新标定所有阈值。

## 5- 输出（output/oven/<YYMMDD_HHMMSS>/）
| 文件 | 内容 |
|---|---|
| `ckpt_best.pt` / `ckpt_last.pt` | 各任务头（及阶段 4 放开的骨干参数 / LoRA）权重，冻结的骨干不保存；last 额外带优化器状态用于续训 |
| `gallery.pt` | 型号特征库：`proj`（Proj Head 特征）和 `raw`（DINOv3 CLS）两套；`meta.fingerprint` 是绑定的权重版本 |
| `calibration.json` | 阶段 2 标定结果：tau、is_oven / food 阈值、容器和附件逐类阈值、层位置信度阈值；`sources` 注明每项是标定值还是默认值 |
| `val_report.json` / `test_report.json` | 用标定后阈值的详细评估：逐类 P/R/AP、层位逐层准确率和按型号的混淆矩阵、型号检索、级联误差 |
| `label_issues.json` | 入库校验的错误与警告明细 |
| `training_metrics.json` / `training_curves.png` | 每轮各项 loss、各头梯度范数、验证指标 |
| `train.log` / `config.yaml` / `device_profile.json` | 日志与本次训练实际使用的配置快照 |
